# 改论文项目规范

## 项目目标

- 审查论文的科学叙事、章节逻辑、段落衔接和术语准确性。
- 参照 Advanced Materials（AM）及同等级期刊标准进行英文润色，但不夸大结论、不补造数据或文献。
- 为正文各部分规划图件，并审查已有图片的科学逻辑、版式和投稿质量。
- 每次工作结束后，将可复用提示词、修改稿、审查报告和作图建议保存到本项目目录。

## 目录约定

- `00_项目说明/`：项目工作流、投稿标准和长期约定。
- `01_参考文献风格/`：参考 PDF 的语言、结构和图件风格分析。
- `02_论文修改/`：用户论文的逐版修改稿及修改说明。
- `03_作图建议/`：图件规划、已有图片审查和绘图脚本。
- `04_提示词/`：可直接复用的论文审查与润色提示词。
- `05_交付记录/`：每轮工作摘要和待办事项。
- `temp/`：可删除的中间提取文件，不作为正式交付物。

## 命名规则

- 正式文件使用中文描述和日期：`YYYY-MM-DD_主题_v01.md`。
- 用户原文件不覆盖；修改稿另存为新版本。
- 图件源文件、数据、导出文件分开保存，保证可追溯。

## 修改原则

- 结论先行，修改必须能追溯到清晰度、准确性、逻辑或期刊规范。
- 区分语言问题、逻辑问题、证据不足和科学性风险，不能用润色掩盖证据缺口。
- 保留术语一致性；无负极锂金属电池默认优先使用 `anode-free lithium metal batteries (AFLMBs)`，首次出现定义缩写。
- 未核实的机理、性能比较和因果关系必须标注，不自行补充为事实。
- 作图先确定“该图要证明什么”，再决定面板、数据和视觉形式。

## 安全边界

- 不删除用户原文件，不覆盖原稿。
- 不修改密钥、环境配置、CI/CD 或系统设置。
- 不执行 git push、rebase、reset 或公开发布，除非用户明确确认。

## 本地文档渲染环境

- LibreOffice Portable 固定安装在 `D:\LibreOfficePortable`；已验证版本为 `26.2.4.2`。后续任务直接使用该版本，不再重复搜索或安装。
- 命令行转换优先调用 `D:\LibreOfficePortable\App\libreoffice\program\soffice.com`；图形界面启动器为 `D:\LibreOfficePortable\LibreOfficePortable.exe`。
- Windows 下为无头转换创建独立用户配置目录时，必须用 `([System.Uri]$profilePath).AbsoluteUri` 生成 `file:///C:/...` 形式的 URI。不得直接拼接 `file://` 与 Windows 反斜杠路径，否则 LibreOffice 会以退出码 1 终止。
- DOCX 修改后的版面验收应完成 `DOCX -> PDF -> 逐页 PNG`，并检查标题、图表、公式、分页、字体替换和文字截断。渲染产物放入 `temp/`，仅作内部核验，不视为正式修改稿。
